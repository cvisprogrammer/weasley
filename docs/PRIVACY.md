# Weasley privacy disclosure — personal prototype

## Gmail reply assistant

Weasley uses Google OAuth with `https://www.googleapis.com/auth/gmail.readonly` after explicit connection approval. A profile request identifies the connected account; thread bodies are read only after Scan. The application queries up to 20 Primary inbox threads per scan. It never sends, deletes, archives, marks read or changes Gmail labels.

Messages travel from Google directly to the user's browser. A pure MIME/HTML parser extracts text without inserting email HTML into the page or requesting remote images, links or attachments. The local WebGPU model receives limited current-thread text and account/alias addresses as data. It does not receive the OAuth token, have email-action tools or contact a developer inference service. No email content or tokens are included in telemetry or logs; there is no telemetry backend.

Raw bodies and MIME are not persisted. Results are held in page memory. Supporting quotes (at most 240 characters), account and matched thread/message IDs for badges are held in trusted `chrome.storage.session` memory, which can survive service-worker suspension but is not persistent disk storage. Visible badges expire after 15 minutes and can be invalidated by observed Gmail row changes; expired records can remain in session memory until cleanup/session end. Persistent local storage contains model data/settings, a badge-enabled preference and up to 500 dismissal hashes derived from account/thread/latest-message identity. Those hashes are metadata and are not promised to be anonymous. Aliases typed for a scan are not saved.

OAuth tokens are managed by Chrome Identity and retained transiently by the API client, never saved in Weasley's local/session storage or request URLs. Tokens are sent only as Gmail authorization headers and in a POST body to Google's official revocation endpoint on Disconnect. The scope is read-only; website host permission for Gmail additionally permits displaying the DOM badge, which Chrome may describe as reading/changing website data. The content script reads account controls and row IDs and changes only its own visual overlay.

Stop halts additional fetching and cancels local analysis. Disconnect clears page results, session badge data, dismissal metadata and Chrome's OAuth cache, stops badge observation and releases the local model. It attempts Google revocation; the UI reports when that cannot be confirmed. The user can also remove the app from Google account connections. Closing the dashboard ends its in-memory scan; existing badges can remain in session memory for the last scan until expiry/disconnect/session end. Website scripts retain their normal access to their own content.

## Models and legacy typing prototype

Model artifacts download from Hugging Face only after explicit Load. Download providers see normal connection metadata such as IP address, not mail/draft content. Executable model libraries are bundled with the extension; models are cached locally. The optional older typing feature reads its current field and a bounded sample of visible same-page context only on websites explicitly allowed for that feature (plus the extension's own test). Other field values, private markers and hidden/navigation content are excluded by heuristics. Context is processed locally and not stored to disk. Up to 500 numeric typing-performance events can be stored locally. The version 0.3+ test page stores no trial results; older HTTP lab data can be cleared in browser site storage.

There are no accounts operated by Weasley, advertisements, analytics, cloud inference calls or developer email storage. Uninstall removes extension-local data subject to Chrome's cache behavior; Google account authorization can also be removed independently. Publisher/support identity, public policy hosting, legal/license review and Google/Chrome distribution disclosures must be completed before public release.
